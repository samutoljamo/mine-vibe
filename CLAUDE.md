## Beads Issue Tracker

This project uses **bd (beads)** for issue tracking. Run `bd prime` to see full workflow context and commands.

### Quick Reference

```bash
bd ready              # Find available work
bd show <id>          # View issue details
bd update <id> --claim  # Claim work

```

### Rules

- Use `bd` for ALL task tracking — do NOT use TodoWrite, TaskCreate, or markdown TODO lists
- Run `bd prime` for detailed command reference and session close protocol
- Use `bd remember` for persistent knowledge — do NOT use MEMORY.md files

**Architecture in one line:** issues live in a local Dolt DB; sync uses `refs/dolt/data` on your git remote; `.beads/issues.jsonl` is a passive export. See https://github.com/gastownhall/beads/blob/main/docs/SYNC_CONCEPTS.md for details and anti-patterns.

## Session Completion

**When ending a work session**, you MUST complete ALL steps below. Work is NOT complete until `git push` succeeds.

**MANDATORY WORKFLOW:**

1. **File issues for remaining work** - Create issues for anything that needs follow-up
2. **Run quality gates** (if code changed) - Tests, linters, builds
3. **Update issue status** - Close finished work, update in-progress items
4. **PUSH TO REMOTE** - This is MANDATORY:
   ```bash
   git pull --rebase
   git push
   git status  # MUST show "up to date with origin"
   ```
5. **Clean up** - Clear stashes, prune remote branches
6. **Verify** - All changes committed AND pushed
7. **Hand off** - Provide context for next session

**CRITICAL RULES:**
- Work is NOT complete until `git push` succeeds
- NEVER stop before pushing - that leaves work stranded locally
- NEVER say "ready to push when you are" - YOU must push
- If push fails, resolve and retry until it succeeds

## Build & Test

**All cmake/make commands MUST run inside the `cyberismo` distrobox** (Vulkan headers, glslc, gcc live there) — never on the host.

```bash
# Configure (first time or after CMakeLists.txt changes; defaults to Release)
distrobox enter cyberismo -- cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
# Build
distrobox enter cyberismo -- cmake --build build
# Run all unit tests
distrobox enter cyberismo -- ctest --test-dir build --output-on-failure
```

- Generator is Unix Makefiles (no ninja in the distrobox). `build/` is gitignored.
- Dependencies are fetched via CMake FetchContent: GLFW, volk, VMA, cglm, stb, FastNoiseLite, miniaudio.
- Run the game: `./build/minecraft` (singleplayer/host by default). Flags: `--render-distance N` (default 12), `--msaa 1|2|4` (default 1=off), `--aniso N` (default 4), `--stats` (perf overlay), `--host` / `--client <ip>` / `--server`.

## Architecture Overview

C11 + Vulkan voxel game (Minecraft-like), single binary that runs an integrated UDP **server thread** (authoritative) plus the **client/renderer** on the main thread; multiplayer uses the same server.

- **Rendering**: Vulkan via volk + VMA. `renderer*.c`, `swapchain.c`, `pipeline.c`, `mesher.c` (chunk meshes), `texture.c` (baked atlas in `assets_generated.c`, generated by `tools/gen_assets.py`). Shaders in `shaders/`, baked to `shaders_generated.c`.
- **World**: `chunk.{c,h}` (16×256×16), `chunk_map.c`, `world.c` (worker-thread chunk streaming), `worldgen.c` + pure helpers `ore.c` / `biome.c` / `village.c`, `lighting.c` (sky + emissive block light), `world_persist.c` (block-delta overlay save/load).
- **Gameplay**: `player.c`, `physics.c`, `block_physics.c`, `mob.c` (zombie/skeleton/creeper), `inventory.c`, `item.c` (unified ItemId: blocks + tools), `survival.c` (hunger/fall/drown/lava/death), `block.c` (BlockDef incl. hardness + `light_emit`), `daynight.c`.
- **Networking**: hand-rolled little-endian packets in `net.h` (helpers + `NET_PROTOCOL_VERSION`, negotiated at the connect handshake — bump it on any wire change), `net.c`, `net_thread.c`, `reliable.c` (acks/retransmit + fragmentation). `server.c` is authoritative (validates block edits/reach against its world); `client.c` + `remote_player.c` interpolate snapshots.
- **UI/Audio**: `ui/ui.c` (immediate-mode + hit-test), `ui/hud.c` (HUD + menus/inventory/crafting screens), `audio.c` (engine + procedural SFX/music) with a pluggable backend (`audio_miniaudio.c`, falls back to silent if no device).
- **Agent mode**: `agent.c` — JSON stdin/stdout control for automated testing (see the `minecraft-agent-mode` skill).

## Conventions & Patterns

- **Pure + tested core**: gameplay logic is factored into pure functions in their own module (no Vulkan/GLFW) with a `tests/test_*.c` unit test wired as a CMake target (see `tests/test_ore.c` as the template). Add new logic this way; TDD (write the failing test first).
- **Adding a block**: enum in `block.h` before `BLOCK_COUNT`, `BlockDef` + representative color in `block.c` with atlas tile indices, a `draw_*` generator + `TILE_GENERATORS`/`TILE_NAMES` entry in `tools/gen_assets.py`, then regenerate with `distrobox enter cyberismo -- python3 tools/gen_assets.py`. Atlas is 256px / 16px tiles; UV = `tile%16`, `tile/16`.
- **Server-authoritative**: gameplay state changes go through the server; clients send requests and apply server broadcasts. New packets use the `net.h` helpers and bump `NET_PROTOCOL_VERSION`.
- **Threads**: chunk-gen workers + net thread + server thread; lazy per-chunk allocs are atomic. Signal threads to stop (e.g. `server_request_stop()`) before joining on shutdown.
